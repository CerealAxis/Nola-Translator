# 疑难解答

本节按故障发生的位置整理检查方法，并说明怎样提交有效反馈。先确定已验证的环节，再处理后续故障，可以减少重复下载和无效重置。

## 一、从现象进入

| 现象 | 先确认什么 | 下一步 |
| --- | --- | --- |
| 软件无法安装或打开 | 系统架构、来源和下载完整性 | [下载与安装](../getting-started/download-and-install) |
| 测试没有声音 | 实际设备、静音、路由和权限 | [音频采集排查](./faq#audio) |
| 试听正常但不能启动 | 引擎、组件、权重、设备和语言 | [启动与组件](./faq#startup) |
| 模型下载或校验失败 | 对应来源、空间与分块状态 | [模型与下载](./faq#downloads) |
| 有原文没有译文 | 翻译开关、语言方向、接口及额度 | [原文与译文](./faq#translation) |
| 浏览器不能连接 | 版本、许可、注册、共享音源 | [浏览器问题](./faq#browser) |
| 记录或录音不见 | 会话类型、保存选项和实际目录 | [记录与数据](./faq#records) |

## 二、按顺序验证

### 先做采集测试

播放目标语音，执行“测试音频”，确认实际回放。如果没有输入，先处理设备，不需要先下载更多模型。

### 再做短会话

采集正常后检查原文，原文出现后检查译文。每次只改变一个配置，保留结果，避免同时换模型、接口和设备后无法判断原因。

### 最后检查显示与保存

区分字幕被隐藏、服务没有产生译文，以及记录未创建。浏览器临时会话不保存桌面会议，不能作为记录故障处理。

## 三、不要过早删除线索

恢复出厂设置不能解决云端余额、第三方限流、驱动不兼容或播放器权限。它也不是完整数据清除工具。模型校验失败时不能通过关闭校验继续运行，凭据泄露则应先撤销密钥。

重装、迁移和清理前，先确认实际数据与日志位置，备份重要记录，并记下版本、错误码和失败时间。

## 四、提交反馈

[如何反馈](./feedback)提供环境与复现模板、日志定位和隐私检查。完整错误、支持码及关联 ID 能帮助将 UI 与引擎诊断对应起来。

日志不自动上传，提交前仍需检查设备名、路径和原始异常。不要公开真实凭据、整份会议目录、浏览器配置或未经许可的音频。

## 五、文档错误与功能建议

步骤与实际界面不符时，给出页面和具体段落，并说明使用版本。建议新功能时，描述需要完成的任务及现有方式的不足。愿意直接修改时，可以按[如何贡献](../contributing/how-to-contribute)提交。
