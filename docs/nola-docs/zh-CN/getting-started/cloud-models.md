# 云端模型配置

>[!TIP]
> AI攥写，待完善

本页介绍远程语音识别、通用大模型翻译、Microsoft Translator、MyMemory 和 Index-Translate 公开 API 的配置。识别和翻译是两条独立链路，可以分别选用本地或远程服务。

使用远程识别时，音频会发送给对应服务；使用远程翻译时，原文及所需上下文会发送给对应接口。开始前先确认费用和数据处理政策，详细范围见[隐私协议](../legal/privacy-policy)。

## 一、先区分服务类型

| 需要完成的任务 | 设置位置 | 服务示例 |
| --- | --- | --- |
| 音频转换为原文 | 设置 → 音频与识别 | 阿里云 LiveTranslate、MiniMax |
| 原文转换为目标语言 | 设置 → 翻译 | 通用大模型、Microsoft Translator、MyMemory 等 |
| 直接使用识别连接的译文 | 设置 → 翻译 | 仅阿里云 LiveTranslate |

通用大模型翻译的 API Key 不会自动用于阿里云或 MiniMax 识别。相同厂商也可能提供多个不同接口，不能只因为密钥属于同一平台就忽略模型权限、地域和 API 格式。

全部使用远程服务时，不需要为了推理安装本地 PyTorch 或 llama.cpp。混合方案则只为本地部分准备组件。

## 二、开始前准备

从服务商官方控制台或文档确认以下信息，而不是从第三方教程复制一组旧值：

| 信息 | 用途 | 常见错误 |
| --- | --- | --- |
| 接口地址 | 决定请求发给谁 | 填成网页控制台或完整请求路径 |
| API 格式 | 决定请求和响应协议 | 把兼容 Chat Completions 的服务选成 Responses |
| 模型 ID | 指定服务端模型 | 只填写厂商名称或界面宣传名 |
| 密钥 | 调用认证 | 填错账户、地域或已撤销的密钥 |
| 地域／空间 | 确定服务资源归属 | 阿里云空间与密钥不在同一地域 |
| 额度与权限 | 判断能否实际调用 | 保存成功后误以为服务已开通 |

价格与免费额度可能变化，本页不把某个临时数值写成长期承诺。使用测试和短会话时，也可能产生服务费用。

## 三、阿里云 LiveTranslate

### 1. 取得所需信息

按[阿里云实时语音翻译文档](https://help.aliyun.com/zh/model-studio/qwen3-5-livetranslate-flash-realtime)准备百炼 API Key、业务空间 ID 和地域。软件支持的地域选项为北京和新加坡，应与实际资源对应。

API Key 是凭据，业务空间 ID 是连接所需的配置字段，两者不能互换。不要把控制台网址或整个 WebSocket URL 填进空间 ID 输入框。

### 2. 填写识别设置

1. 打开“设置 → 音频与识别”。
2. 将“服务商”设为“阿里云 LiveTranslate”。
3. 在“识别模型”中选择软件提供的 3.8 或 3.5 模型。
4. 选择与服务资源一致的“区域”。
5. 填写“百炼业务空间 ID”，再在“API 密钥”输入框填写密钥并离开输入框保存。
6. 核对“原文语言”，然后完成本地音频测试。

| 模型选项 | 原文语言设置 | 使用时注意 |
| --- | --- | --- |
| `qwen3.8-livetranslate-flash-realtime` | 自动检测 | 不能依靠界面手动语言覆盖其服务方式 |
| `qwen3.5-livetranslate-flash-realtime` | 可按支持范围指定，也可自动 | 语言须在软件与服务共同支持的范围内 |

### 3. 选择译文来源

需要阿里云同一连接返回的译文时，到“设置 → 翻译”选择阿里云服务。该模式复用识别连接，不需要再创建一个通用大模型翻译地址。

也可以选择其他翻译服务，此时原文会交给独立翻译链路处理。这样不会取消阿里云识别费用，还可能增加另一服务的费用和数据接收方。

### 4. 验证与排错

用短语音开始会话，确认原文和目标译文分别出现。结束时等待尾句完成，不直接退出进程。

认证失败先查地域、空间、密钥和服务权限；有原文但无译文先查翻译服务与目标语言。不要把云端账号问题误判为缺本地模型。

## 四、MiniMax 语音识别

### 1. 理解输出时机

MiniMax Speech-to-Text 接收完整音频文件。软件先按停顿切段，再上传 WAV，返回的流式响应只发生在上传后。因此它不会像持续音频输入接口一样，在片段尚未结束时就逐字回传。

当前引擎使用 6 秒分段上限控制连续语音的等待预算，这是应用分段策略，不是 MiniMax 服务的上传时长上限。部分旧界面提示可能未同步，不能以旧提示推断实际切段行为。

### 2. 填写连接

1. 在“音频与识别”选择“MiniMax 语音识别”。
2. 选择 `asr-1.0`，核对账户所在服务端点。
3. 在“接口地址”填写该识别接口的地址；它不是通用大模型的 Chat Completions 基础地址。
4. 保存 MiniMax 识别密钥。
5. 选择受支持的原文语言，完成音源测试，再开始短会话。

软件随配置提供识别端点默认值。使用其他地区账户时，应根据[MiniMax 识别接口文档](https://platform.minimax.io/docs/api-reference/speech-to-text)核对，不要仅凭域名相似自行替换。

### 3. 配置独立翻译

MiniMax 识别不自带本项目可用的译文，需要在“翻译”中另选服务或本地模型。把翻译设为阿里云连接译文不能让 MiniMax 返回译文。

若字幕通常在停顿处出现，先判断是否符合分段方式；若持续没有字幕，再检查网络、密钥和错误码。余额不足与限流应分别处理，不能通过反复开始会话绕过。

## 五、通用大模型翻译

### 1. 打开连接设置

在“设置 → 翻译”将“服务商”设为“云端模型”。这里表示通过通用 API 协议调用模型，也包括指向本机 Ollama 的配置；数据是否出机由实际接口地址决定。

![通用大模型翻译的连接设置](/docs-image/zh-CN/getting-started/cloud-models/cloud-translation-settings.png)

截图使用演示配置，不含密钥。地址和模型示例仅用于解释字段，实际填写以服务商文档为准。

### 2. 按 API 格式填写基础地址

| API 格式 | 应填写的地址层级 | 软件使用的请求路径 |
| --- | --- | --- |
| Chat Completions | 通常包含 `/v1` 的 API 基础地址 | 在基础地址后追加 `/chat/completions` |
| Chat Responses | 对应 Responses 的 API 基础地址 | 追加 `/responses` |
| Anthropic Messages | 按提示填写站点根地址 | 追加 `/v1/messages` |
| Ollama | Ollama 主机地址，例如 `http://127.0.0.1:11434` | 追加 `/api/chat` |

例如，若服务文档给出完整请求地址 `https://api.example.com/v1/chat/completions`，Chat Completions 基础地址通常填写 `https://api.example.com/v1`。`api.example.com` 是不可用于实际服务调用的占位域名，必须替换。

不要同时填入完整请求路径又让软件追加路径。服务若有自定义前缀，应根据其协议核对，不能一律删除所有路径。

### 3. 逐项填写

| 字段 | 填写方法 | 说明 |
| --- | --- | --- |
| 名称 | 自己能识别的配置名称 | 不作为服务端模型选择依据 |
| 接口地址 | 上表对应的基础地址 | 优先使用受信任的 HTTPS 服务 |
| API 密钥 | 对应服务提供的有效凭据 | 离开输入框后保存，不填在 URL 中 |
| API 格式 | 服务实际支持的协议 | “兼容 OpenAI”不代表同时支持两种 API |
| 模型 ID | 服务端可调用标识 | 大小写及后缀按服务说明填写 |
| 上下文窗口 | 不超过服务能力的合理值 | 影响保留上下文与请求预算 |
| 最大输出 Token | 足以容纳目标译文 | 过小可能截断，过大不保证翻译更好 |

修改 API 格式后重新核对地址和模型。软件只会在部分默认配置之间替换默认值，自定义值不能假定自动适配另一种协议。

### 4. 密钥检查与真实验证

“检查密钥”只检查本机是否存在可读取的已保存凭据，不会向服务商发送测试请求，也不验证余额、模型权限或接口连通性。成功提示不能作为远程连接成功的证据。

先用本地音频测试确定输入正常，再用短会话确认“有原文、有译文、目标语言正确”。翻译失败时保留状态和错误，不要先重复更换识别模型。

## 六、Microsoft Translator

在翻译服务中选择“Microsoft Translator”，按资源信息填写接口地址、区域及密钥。该选项使用文字翻译接口，不是通用大模型 Chat Completions，也不承担语音识别。

接口地址与区域需要匹配实际 Azure 资源；仅有一个其他 Azure 服务的密钥并不代表可以调用翻译。可对照[Microsoft Translator Translate 接口](https://learn.microsoft.com/en-us/azure/ai-services/translator/text-translation/reference/v3/translate)确认资源要求。

保存后使用短句会话验证。若出现认证或区域错误，应先核对资源而不是修改本地推理组件。

## 七、无需密钥的翻译服务

### 1. MyMemory

选择“MyMemory 免费翻译”，保留官方接口或填写受信任的兼容端点，可选提供联系邮箱。邮箱不是 API Key，填写后会随服务请求发送。

MyMemory 对确认句子执行 REST 翻译，不逐字推送译文，也不为每个过时中间识别修订发起翻译。免费服务有配额、限流和业务错误，HTTP 请求成功不等于译文一定有效。

### 2. 哔哩哔哩公开 API

选择“哔哩哔哩 免费API”后，软件使用固定的官方公开 Index-Translate 连接和模型，不消耗通用云端密钥。选择目标语言后，应通过项目维护的语言预设校验。

这会发送待翻译文字，不是在本机运行 Index-Translate。无需密钥也不等于没有额度、永不停止或适合发送敏感内容。

## 八、未定稿翻译和备用服务

### 1. 是否翻译未定稿字幕

识别内容可能在一句完成前继续修订。对支持的独立翻译服务，开启“翻译未定稿字幕”可更早看到译文，但可能产生额外请求、费用及反复调整的文字。

只需要稳定结果时关闭该项。MyMemory 和阿里云识别连接自带译文有各自的处理方式，不能用这一开关承诺相同效果。

### 2. 配置备用翻译

在“备用翻译”中选择备用服务，并填写它自己的连接配置。主翻译连续失败后，软件尝试用备用服务处理定稿字幕，不代表整个识别会话会换到另一个 ASR 服务。

本地备用使用选中的本地翻译模型；主、备用云端模型可以使用不同连接配置。其他不允许重复的同类服务会受选择限制。保存后检查备用语言能力、凭据和费用，避免主服务失败后才发现备用也无效。

> [!WARNING] 备用服务的数据去向
> 原文可能在主服务已接收后再次发送给备用服务。需要本地处理的场景，应同时检查主翻译和备用翻译，而不只检查识别方式。

## 九、按错误现象检查

| 现象或错误 | 优先检查 | 不应优先进行的操作 |
| --- | --- | --- |
| 认证失败／无权限 | 密钥、地域、空间和服务开通 | 重装完整本地模型 |
| 余额不足 | 账户余额、账单和套餐 | 连续重复发送相同请求 |
| 请求限流 | 并发、未定稿请求和等待时间 | 当成余额不足处理 |
| 404／路径错误 | API 格式与基础地址层级 | 随意替换密钥 |
| 模型不存在 | 准确模型 ID 及权限 | 填写厂商宣传名 |
| 有原文无译文 | 翻译开关、目标语言、服务结果 | 反复切换音频设备 |
| 网络超时 | 端点可达性和实际网络路径 | 假定下载代理覆盖所有推理请求 |

反馈前按[如何反馈](../troubleshooting/feedback)检查日志，隐藏密钥、内部端点和个人信息。不要把包含认证头的完整请求贴到公开 Issue。
