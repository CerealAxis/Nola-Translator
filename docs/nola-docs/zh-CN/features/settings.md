# 系统设定

>[!TIP]
> AI攥写，待完善

本页按设置页结构解释各组选项、适用范围和修改后的验证方法。详细安装和服务开通流程分别见[环境配置](../getting-started/environment)与[云端模型配置](../getting-started/cloud-models)。

设置通常自动保存，但设备、性能和存储变更可能对后续会话或重启后生效。修改前应先结束会话，留意保存错误及重启提示，不把控件显示变化当作已经成功持久化。

## 一、常规

### 1. 主题、语言与动效

主题可按系统或选择浅色、深色。它影响主界面，不等于同时修改悬浮窗和浏览器字幕的独立配色。

界面语言可以自动跟随系统区域，也可以手动指定。界面语言、识别原文语言和翻译目标语言分别设置；把界面改为日语不会让当前识别模型自动支持日语。

减少动效用于降低装饰性运动，对识别速度和模型能力没有提升作用。

### 2. 网络与下载

| 选项 | 负责的范围 | 调整时注意 |
| --- | --- | --- |
| 代理服务器地址 | 提供代理位置 | 地址必须真实可用，留空表示不用 |
| 将代理应用到 Pip | Python 依赖安装 | 不代替正确的包索引 |
| 将代理应用到模型下载 | 模型权重请求 | 与模型下载源共同决定路径 |
| 将代理应用到组件下载 | 运行包下载 | 不应假定覆盖所有云推理请求 |
| PyPI 镜像 | Python 包获取 | 选择受信任节点 |
| Hugging Face 镜像 | 对应模型下载 | 不代表所有 ModelScope 来源都受影响 |
| GitHub 加速 | 镜像未覆盖的 GitHub 分发 | 自动选择与手动节点分别核对 |

下载变慢时先确定失败的资源类型。不要同时更换所有镜像与代理，否则难以知道哪一项起作用。恢复直连也应一次改变一类设置。

## 二、音频与识别

### 1. 音频来源

系统输出用于电脑播放声音，麦克风用于现场输入。指定设备与默认输出不同，更换耳机或播放路由后需要重新验证。

“测试音频”会采集两秒并回放识别输入，不加载模型或创建记录。成功提示还应结合实际回放判断是否选对声音；静音可能是设备无信号，也可能是测试时没有播放内容。

### 2. 识别服务与语言

选择本地模型时，先确认权重、引擎和计算设备。选择阿里云或 MiniMax 时，页面会显示相应连接字段，密钥分别保存，不与通用翻译密钥混用。

原文语言列表受所选模型和服务约束。切换服务后重新核对语言与翻译配置，不能假定旧设置在新服务中仍然适用。

### 3. 保存录音

开启后，桌面同传可保留音频供记录详情回放。关闭只影响之后对应会话的保存，不会恢复或删除已有录音。浏览器临时会话不因这个开关而成为桌面录音会话。

录音可能包含整段系统输出，不能只按屏幕上的字幕判断采集内容。需要分享时先检查音频本身。

## 三、翻译

### 1. 服务选择

| 服务 | 配置重点 | 数据与资源 |
| --- | --- | --- |
| 本地模型 | 选择权重和有效语言方向 | 本机算力与模型内存 |
| 云端模型 | API 格式、基础地址、模型 ID 和密钥 | 原文与上下文发送给所填接口 |
| Microsoft Translator | 端点、区域和密钥 | 独立文字翻译服务 |
| MyMemory | 接口及可选联系邮箱 | REST 定稿句子翻译，有配额 |
| 哔哩哔哩 免费API | 受支持的语言方向 | 官方公开服务，文字发送远程 |
| 阿里云连接译文 | 必须使用阿里云识别 | 复用识别连接 |

不需要译文时关闭翻译。仅隐藏译文并不等于不再调用翻译服务，应检查服务及目标语言设置。

### 2. 密钥的保存、检查与删除

在相应输入框粘贴密钥，离开输入框后保存。界面用掩码表示已保存，不显示实际密钥。输入空白不应当成可靠删除方式，需要删除时使用“删除密钥”。

“检查密钥”只确认本机保存的凭据可以读取，不调用远程测试接口。保存或检查成功都不能证明账户余额、模型权限或网络连通性正常。迁移 Windows 用户或电脑后，原加密凭据可能无法解密，应重新输入。

### 3. 未定稿和备用翻译

开启未定稿翻译可能增加请求并使文字随原文调整。MyMemory 和识别连接自带译文按自身方式处理，开关不保证所有服务具有相同输出时机。

备用服务在主翻译多次失败后处理定稿字幕，可能增加远程接收方和费用。配置前检查备用语言、密钥和本地资源，不只检查主服务。

## 四、计算设备

“推理引擎”指定任务使用的引擎方向，“检测到的系统显卡”显示硬件信息，“可用计算设备”显示当前后端可用项，三者不能混为一谈。

分别设置“语音识别设备”和“本地翻译设备”。自动分配适合先建立可运行配置，手动指定适合明确知道后端和资源分配的场景。运行后用“当前运行分配”确认实际结果。

“GPU 失败时回退 CPU”只处理允许回退的设备失效或资源情况，不会自动换用另一张被指定的显卡，也不会修复模型不兼容或云端权限。

运行组件管理位于页面下方。安装、重新检查、强制重装和修复的区别见[环境配置](../getting-started/environment)，不要用重装替代所有排错。

## 五、性能与显存

这些设置通常影响下一次启动的任务。不同模型加载器支持范围不同，应先保持默认、完成短会话，再一次调整一个变量。

| 设置 | 含义 | 选择方法 |
| --- | --- | --- |
| 计算精度 | PyTorch 模型的 FP32／FP16／BF16 等 | 优先自动；硬件和加载器必须支持 |
| 模型量化 | 对支持模型使用运行时 NF4／8bit 等 | 不适用于改写 GGUF 文件量化 |
| 保留显存（MiB） | 给系统、其他应用和峰值留余量 | 两任务共卡时考虑总预算 |
| CPU 线程上限 | 控制可使用的线程预算 | `0` 为自动，过多不保证更快 |
| 翻译 GPU 卸载层数 | llama.cpp 翻译放到 GPU 的层数 | `-1` 自动，`0` 为 CPU 路径 |
| 翻译上下文长度 | 本地 llama.cpp 上下文预算 | 增大将增加缓存资源需求 |
| llama Flash Attention | 相应后端注意力实现 | 优先自动，强制启用前确认支持 |

远程翻译页的“上下文窗口”和这里的本地上下文长度不是同一设置。前者关系远程请求，后者关系本机 llama.cpp 缓存。

遇到显存不足时，先缩小模型或上下文，检查总占用，再调整卸载和保留预算。不要通过把所有限制都拉到最大来解决问题。需要回到基线时使用页面的恢复默认入口，只恢复相应组的设置。

## 六、悬浮字幕与浏览器字幕

### 悬浮字幕

调整独立字幕窗的字体、两种文字大小、字重、行距、颜色、背景和布局。对照实际背景检查，不只看预览。操作方法见[悬浮字幕](./floating-captions)。

### 浏览器字幕

管理 Chrome／Edge 的连接权限、安装状态和网页内字幕样式。浏览器自己的扩展开关仍需在浏览器管理页处理，Nola 的许可开关不会替代它。网页字幕样式独立于悬浮窗。

## 七、存储

### 1. 查看实际数据位置

新安装通常将数据放在程序旁的 `Data`，已有安装可能沿用历史目录，用户还可指定其他位置。实际路径以“保存位置”及诊断为准，不以安装程序目录推断。

该位置管理配置、加密凭据、会议、模型和组件。页面占用数字用于说明目录中可读取内容的大小，不等于整块磁盘剩余空间。

### 2. 迁移步骤

1. 结束所有会话与组件任务，备份重要记录、笔记和录音。
2. 在“存储”使用“浏览”选择目标目录，确认磁盘有空间且持续可用。
3. 阅读迁移及重启提示。选择路径时不会立即把所有文件搬走。
4. 按提示重启，等待启动阶段执行迁移。
5. 重新检查实际路径、模型列表和旧记录，再开始新会话。

不要在等待迁移时手动剪切部分子目录，也不要让不同版本同时操作同一数据。跨电脑迁移的凭据可能需要重新填写。

## 八、高级

### 1. 引擎与诊断

查看引擎状态、版本和通信信息。引擎已就绪只说明进程能通信，不表示已开始采集或模型已完成真实推理。

高级页只读展示诊断字段。“复制诊断信息”和“打开日志目录”操作位于“设置 → 更多 → 问题反馈”，前者写入剪贴板，后者定位本次日志。日志可能含设备名称和本地路径，分享前检查，详见[如何反馈](../troubleshooting/feedback)。

### 2. 恢复出厂设置

该操作恢复偏好，不是完整删除工具。模型、记录和模型存储位置保留，也不能以此认定服务商密钥已被撤销。

需要解决单一连接错误时，优先修正该配置。需要删除凭据时使用对应“删除密钥”；需要清除记录时在记录页操作；需要撤销泄露密钥时还须到服务商账户处理。

## 九、更多与开发者选项

“更多”提供项目、开源声明、反馈、日志入口及再次查看教程。再次查看不会重新下载模型或重置推理偏好。赞助空位只是空位，不代表存在未显示的支持者名单。

“开发者选项”用于检查组件和界面状态，不是普通用户完成配置的必经步骤。演示对话框和虚构数据不代表真实调用成功，问题排查仍应以实际会话和日志为准。

## 十、如何确认修改生效

先确认没有保存错误，再按设置类型验证：主题看即时界面；音源听两秒测试；模型与设备新建短会话；接口检查实际译文；存储重启后核对路径和旧数据。一次修改多项时，应逐项记录，否则难以判断故障来源。
