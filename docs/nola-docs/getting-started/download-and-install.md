# 下载与安装

>[!TIP]
> AI攥写，待完善

本页介绍 Windows x64 桌面端的获取、安装、首次检查、升级和卸载。模型及 PyTorch／llama.cpp 运行组件按需配置，不需要为了首次打开软件预先下载全部模型。

## 一、确认安装对象

Nola Translator 的配套资源有不同用途，下载时先区分：

| 资源 | 用途 | 能否单独完成字幕识别 |
| --- | --- | --- |
| 桌面 EXE／MSI 安装包 | 安装主程序、基础引擎和配套资源 | 仍需完成模型或服务配置 |
| 浏览器扩展 ZIP | 在 Chrome／Edge 视频页显示字幕并连接桌面 | 不能，必须有桌面端配合 |
| 模型权重 | 提供本地识别或翻译能力 | 不能，仍需运行组件 |
| Source code | 开发者查看和构建源代码 | 不能直接当安装程序运行 |

用户不需要同时安装 EXE 和 MSI，两者是同一桌面应用的不同安装方式。开发构建与正式发布包也应区分，不能只按文件名中的版本数字判断来源。

## 二、下载前准备

### 1. 查看系统类型

打开 Windows“设置 → 系统 → 系统信息”，检查系统类型。项目发布的桌面安装包面向 Windows x64，不能把它当作原生 ARM64、macOS 或 Linux 包。其他平台的计划不等于已提供安装支持。

如需 GPU 推理，额外核对显卡和驱动。安装成功仅说明程序可部署，不代表当前显卡与所有组件后端兼容，详见[环境配置](./environment)。

### 2. 准备保存空间

选择有写入权限、连接稳定的安装位置。后续权重、运行组件、未完成下载缓存和录音会继续占用空间。不要只按 EXE 大小为整个应用预留容量。

重要数据应另行备份，尤其是在覆盖旧安装或迁移数据前。对已有安装，先在存储设置确认实际数据位置，不能假定所有文件都位于程序目录内。

## 三、从官方发布页下载

1. 打开 [Nola Translator Releases](https://github.com/CerealAxis/Nola-Translator/releases/latest)。
2. 阅读对应发布说明，确认版本、已知问题及安装要求。
3. 展开发布附件，选择 Windows x64 的 EXE 或 MSI。发布流水线使用 `Nola-Translator-版本号-Windows-x64-Setup.exe`／`.msi`；本地默认构建可能使用 `Nola-Translator-版本号-Setup-x64.exe`／`.msi`，以发布说明和附件为准。
4. 下载完成后核对文件名和来源，再启动安装程序。不要选择 `Source code` 压缩包作为安装包。

如果链接没有对应发布，或附件下载不完整，应检查发布状态及网络，不要根据文件名自行拼接未知下载地址。开发测试包只在清楚其用途时使用；可能包含尚未完成验证的改动。

### 校验下载文件

发布附件提供 `SHA256SUMS.txt` 时，同时下载该文件。打开 PowerShell，切换到下载目录，把下面的文件名替换为实际安装包名：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '.\Nola-Translator-版本号-Windows-x64-Setup.exe'
```

将 `Hash` 与校验文件中相同文件名的摘要比较。摘要不同应重新下载，不要继续安装。相符能帮助发现传输损坏，但仍应确认校验文件与安装包来自可信的同一发布。

## 四、执行安装

### 1. EXE 安装

运行 EXE，按向导选择安装目录和快捷方式。目标目录需要允许当前用户写入。完成后通过桌面或开始菜单快捷方式启动 Nola Translator。

安装过程中出现文件占用时，先退出旧版本及其正在运行的会话，再重试。不要在仍保存录音或下载模型时强行替换文件。

### 2. MSI 安装

MSI 使用 Windows Installer。按安装程序提示完成部署；组织管理环境可使用其既有部署流程，但应核对本项目包的实际选项。不要直接套用其他软件的静默安装参数。

### 3. 系统安全提示

系统拦截或安全软件告警时，应先确认文件来自项目仓库，检查发布说明和完整下载情况。无法确认来源时停止运行，并保留告警信息反馈。

不建议关闭整个系统防护、排除整个磁盘或运行未知修复工具。这些操作不能证明安装包可信，也无法解决错误架构或损坏下载。

## 五、首次启动

![Nola Translator 首页与主要功能入口](/screenshots/zh-CN/guide/home.png)

截图为真实页面的虚构演示状态，不包含真实会议。

### 1. 查看引导

首次启动会先显示欢迎页面，可以开始教程了解入口，也可以稍后再看。GitHub Star 邀请是可选项，不影响软件配置。重新查看时进入“设置 → 更多”，使用“再次查看”。

引导只解释功能，不会代为安装组件、下载权重或采集音频。看完教程后仍需自行选择运行方式。

### 2. 选择运行路线

- 需要在本机处理音频和文字时，先按[环境配置](./environment)准备组件，再按[本地模型配置](./local-models)下载权重。
- 已有远程服务凭据时，按[云端模型配置](./cloud-models)填写识别和翻译连接。
- 只需原文字幕时，可以只配置识别并关闭翻译。

本地和远程可以混用，例如本地识别配合远程翻译。要按两部分分别考虑算力、费用和数据去向。

### 3. 验证输入

在“设置 → 音频与识别”选择音频来源，播放语音或对麦克风说话，再点击“测试音频”。听到目标内容的两秒回放，说明采集路径基本正确；若没有信号，先检查设备和系统音量。

测试不会加载权重，也不会创建同传记录。完成模型或服务配置后，还需要用短会话验证真正的识别及翻译。

## 六、升级与迁移

### 1. 升级前

结束所有字幕会话，等待记录写入及下载任务处理完成。记录当前版本、实际数据目录和所用模型，备份重要字幕、笔记及录音。加密凭据不应通过公开附件备份，也不能保证复制到另一台电脑后仍可解密。

### 2. 安装新版本

从项目 Releases 获取新包，按该版本的说明更新。不要同时混用多个不同版本的程序指向同一套活动数据。更新完成后检查记录、模型和设置是否可见，再开始会话。

### 3. 同步浏览器扩展

扩展有独立版本。桌面端提示不兼容时，从配套入口取得扩展、更新已解压目录并在浏览器管理页重新加载，然后刷新原来的视频页面。只重启扩展后台可能无法替换旧页面里的内容脚本。

### 4. 改变数据位置

使用“设置 → 存储”的浏览入口选择新位置，按提示重启，让迁移流程在启动时执行。不要一边运行会话一边手动剪切 `models`、`meetings` 或配置文件。完成后核对实际路径和内容，详见[系统设定](../features/settings)。

## 七、卸载与清理

先结束会话并退出应用，再通过 Windows 的应用管理或对应卸载程序移除。卸载程序、清理用户数据和撤销服务商密钥是三个不同动作。

需要清除隐私数据时，确认实际数据根目录和日志目录，备份后再处理。导出到其他位置的 TXT／SRT／VTT、复制的录音、云盘备份和已发布附件需要分别删除。本机删除不等于远程服务同步删除。

详细数据范围见[隐私协议](../legal/privacy-policy)。恢复出厂设置只恢复偏好，不是完整卸载或数据擦除工具。

## 八、安装后常见问题

| 现象 | 检查顺序 |
| --- | --- |
| 压缩包里没有安装程序 | 确认是否下载了源代码或浏览器扩展 |
| 安装程序无法启动 | 核对 x64 系统类型、下载完整性和安全提示 |
| 界面打开但无法识别 | 检查组件、权重或远程服务配置，不把它当作安装失败 |
| 旧记录不见了 | 先确认实际数据位置，避免重置和覆盖 |
| 更新后扩展不能开始 | 检查扩展版本，重新加载扩展并刷新视频页 |

仍无法解决时，按[如何反馈](../troubleshooting/feedback)提交版本、具体步骤、完整提示和经检查的本次日志。
