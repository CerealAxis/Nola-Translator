# 开始入门

Nola Translator 的首次配置分为音源、识别、翻译和运行环境四部分。按下列顺序准备，可以先确认哪一层已经工作，避免把下载、采集或服务认证问题混在一起。

如果已经配置完成，只需要了解操作，可直接阅读[快速同传](../features/live-translation)、[悬浮字幕](../features/floating-captions)或[浏览器字幕](../features/browser-captions)。

## 一、认识运行链路

```text
系统输出／麦克风／浏览器音频
  → 语音识别得到原文
    → 按需翻译为目标语言
      → 显示字幕
        → 桌面会话保存确认内容（浏览器为临时会话）
```

识别模型不负责决定界面语言，翻译服务也不自动获取音频。可以只识别不翻译，也可以本地识别配远程翻译。三种语言设置分别是界面显示、音频原文和译文目标。

## 二、选择本地或远程方案

| 方案 | 需要准备 | 使用时注意 |
| --- | --- | --- |
| 本地识别、本地翻译 | 对应组件及两类权重 | 本机内存、显存和处理速度 |
| 本地识别、远程翻译 | 本地识别环境及翻译连接 | 原文会发给翻译方 |
| 远程识别、本地翻译 | 识别凭据及本地翻译环境 | 音频发给识别方，译文仍用本机算力 |
| 远程识别、远程翻译 | 网络、服务权限、额度及连接 | 可能分别向两方发送音频和文字 |
| 仅识别 | 有效识别路径，关闭翻译 | 不需要为了原文下载翻译权重 |

更少下载不代表没有费用，免费接口也不等于无限额度。处理敏感内容前，先看[隐私协议](../legal/privacy-policy)确认数据去向。

## 三、首次配置顺序

### 第一步：安装桌面端

按[下载与安装](./download-and-install)取得 Windows x64 EXE 或 MSI，核对发布和来源。浏览器扩展 ZIP、源代码和模型文件不能代替桌面安装包。

### 第二步：准备运行组件

使用本地任务时按[环境配置](./environment)选择 PyTorch／llama.cpp 及计算设备；全部远程时，不必安装未使用的推理组件。安装包已含 Python 3.12 基础环境，普通用户无需另建开发 `.venv`。

### 第三步：设置模型与连接

本地方案按[本地模型配置](./local-models)下载、配置和启用；远程方案按[云端模型配置](./cloud-models)分开设置识别和翻译。混合方案分别完成对应部分。

### 第四步：验证音频

选择实际音源，播放语音并执行两秒测试。确认听到目标内容，再开始会话。该测试不加载权重，也不验证远程凭据。

### 第五步：运行短会话

用非敏感短语音开始，确认原文、译文、语言方向和实际设备。正常结束后检查桌面记录；浏览器临时会话则不创建记录。

## 五、遇到问题时

先区分阶段：无回放检查采集；回放正常却不能启动检查组件和模型；有原文没译文检查翻译。不要一开始重置全部偏好。

按[常见问题](../troubleshooting/faq)排查，仍失败时保留原错误与日志，按[如何反馈](../troubleshooting/feedback)提交。网页演示有字幕只是内存演示正常，不能作为本机环境已经配置的依据。
