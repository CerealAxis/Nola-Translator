# 包容性

从不同用户的使用目标和处境出发设计内容。检查文字、图像和操作时，考虑语言、文化、能力和生活经历如何影响理解。

## 包容性设计

通过观察和访谈了解不同用户怎样完成同一任务。用真实的名字、长译文和不同书写方向试用原型，也在嘈杂、静音或无法使用鼠标时走一遍关键流程。

## 友好用语

用简单、准确的动词和用户熟悉的名词。首次出现的术语在需要理解的位置解释。选择「发言人」「参与者」等与场景相关的称谓，避免用俚语、双关和笑话承担关键说明。

## 易于上手

用常见的组件和直白的入口名称降低学习成本。让用户可以先做一项任务，再逐步了解高级设置。首次使用时提供帮助，也允许已经熟悉任务的用户直接进入工作区。

## 性别认同

没有必要收集性别时，省去这一字段。用姓名或角色称呼会议参与者，让用户选择对外显示的名字。系统需要账户标识时，把它与显示名称分开处理，容纳不同文字、长度和顺序的姓名。

## 用户和背景

人物图像、文档示例与场景可以呈现不同年龄、能力和生活环境。测试例子时请熟悉相关语言和文化的人审阅，确认含义与预期一致。

## 避免刻板印象

选择通用的人形图标表示账户或身份。人物的外貌、声音与称谓不能作为推断身份、职业或能力的依据。

## 无障碍

同一信息应有多种感知和操作途径。示例中的音频状态同时写成文字，悬停动作也能通过键盘发现。媒体、界面字号和操作方式允许按需调整。

## 语言

区分界面语言、原文语言和译文语言。语言选择列表使用语言自身的名称。日期、数字、单位和货币遵循用户区域设置，预留翻译后的增长空间。验证状态色和符号在各地区仍传达同样的含义。
