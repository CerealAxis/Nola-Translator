# App 图标

鲜明、简洁的 App 图标帮助用户在桌面、任务栏、搜索结果和通知中找到应用。同一个图标在不同位置出现时，应保留容易辨认的轮廓和核心图形。

## 分层设计

制作图标时，将背景、主体和必要细节分别保留在设计源文件中。前景边缘清楚，背景衬托主体，缩小后各部分仍能分辨。需要透明度时，检查重叠区域会怎样改变颜色与轮廓。

使用矢量图形保存平面形状与文字轮廓，便于导出不同尺寸的资源。包含渐变、纹理或细小图案时，同时检查最终位图，确认细节在小尺寸下仍然清楚。

## 图标形状

图标的外形需要适应所在系统的展示方式。把主要内容放在安全区域内，四周留出足够空间，让任务栏缩略图、系统裁切和不同背景都能完整呈现主体。

使用平台要求的原始画布和交付格式，由相应构建流程生成应用图标。系统负责的遮罩、圆角与阴影应在目标环境中检查，避免将一套装饰效果重复叠加到所有输出。

## 设计

用一个容易记住的概念表达应用。保留最能代表产品的形状，减少精细线条、尖角和装饰，让主体在大型展示与小型图标中都有清楚的轮廓。

各平台沿用相同的核心设计。名称通常已显示在图标旁，图标内部只保留品牌识别必需的字符或符号。版本号、宣传语和临时状态放在相应界面中。

插图应突出内容特征。绘制简洁的图形，检查重叠形状与背景的关系，避免让照片细节或完整界面缩略图掩盖主体。

## 视觉效果

阴影、高光和透明效果需要与系统提供的效果协调。将必要效果保留在可编辑层中，分别检查静止、聚焦和不同背景下的结果。过强的发光、模糊或立体边缘会损失小尺寸图标的清晰度。

图标的辨识主要来自形状和构图。确定基本图形后，再判断视觉效果是否确实有助于表达层次。

深色背景中保留柔和、清楚的颜色。透明边缘、暗色笔画和细小空隙需要单独检查。制作外观变体时，成组比较各版本，确保用户切换外观后仍能立即找到同一个应用。

检查最终发布资源在 16、24、32 和 64px 等实际尺寸中的表现。大尺寸预览清晰之后，还需确认任务栏、窗口列表和系统通知中的显示结果。
