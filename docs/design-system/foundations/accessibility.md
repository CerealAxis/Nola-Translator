# 无障碍

让用户能看见、听见或通过辅助技术感知内容，并用熟悉的方式完成操作。设计时同时考虑长期的能力差异和日常情境，例如屏幕反光、环境嘈杂或只能单手操作。

## 视觉

**允许放大文字。** 界面正文采用 14px，长篇阅读采用 17px。放大至 200% 时，让标签、段落和错误说明换行，让控件随内容增高。原文和译文并排放不下时可以改为上下排列，保留对应关系。

**检查实际前景与背景的对比度。** 普通正文与背景至少达到 4.5:1，识别控件所必需的边界和焦点标记至少达到 3:1。分别检查浅色、深色及各种控件状态。字幕衬底还要在实际画面上检验。

**给颜色补充形状和文字。** 同样的点形只换红绿颜色，用户可能分不清状态。加入不同的符号和简短的状态词，在灰度显示中也能识别结果。

**让屏幕阅读器理解界面。** 提供语义化的标题、列表、表单和表格。标签关联字段，错误关联到对应输入，图标按钮有可访问的名称。内容图片提供替代文字，装饰图形从无障碍树中隐藏。

## 听觉

**给语音和声音提示提供文字。** 用实时字幕呈现对话，用记录保留可回看的全文。用于无障碍观看的字幕还应描述说话者及影响理解的声音。提供字幕字号和衬底设置。

**让声音反馈有可见的对应。** 开始采集、连接失败和播放结束都要在相关位置显示状态。即使系统静音，用户也能判断发生了什么和如何继续。

## 肢体活动能力

**让操作目标易于命中。** 桌面按钮和图标按钮至少高 36px，触控目标至少为 44 × 44px。相邻按钮使用 8px 间距，避免命中区重叠。16px 图标置于完整的按钮命中区中。

**为手势提供等效操作。** 拖放文件可用「选择文件」替代，拖动排序可用「上移」「下移」。语音控制使用可见的操作名称，辅助输入设备可以通过标准控件完成相同操作。

**让核心流程可通过键盘完成。** 按页面阅读顺序移动焦点，保留系统快捷键。使用 2px 焦点轮廓和 2px 间隔，打开对话框时移入焦点，关闭后回到触发位置。允许用开关控制等辅助技术逐项操作。

## 语音

**为不同语音能力保留文字途径。** 用户可能无法清楚发音、暂时不能讲话，或更习惯通过文字交流。语音输入旁提供文本输入与文件导入，让用户自行选择表达方式。

**允许使用辅助沟通方式。** 接受用户键入、粘贴或通过辅助输入生成的文字。需要交流的内容可以用文字呈现，并保留朗读等可选方式。

## 认知能力

**让界面可预测。** 保持操作名称和位置稳定，复杂任务按步骤推进。在用户需要作决定时，明确写出后果与下一步。

**留足阅读和反应时间。** 需要处理的错误保持可见，重要结果留在任务页面。自动播放的媒体应有暂停与停止入口，减少动态效果偏好开启时直接显示新的状态，避免闪烁和大幅位移。
