# 编写

文字帮助用户认出内容、判断下一步并从错误中恢复。开始写之前先看页面里的操作顺序，再决定标题、标签和说明各自承担什么。

## 入门指南

**建立一致的风格。** 使用直接、平实的表达，给同一个对象使用同一个名字。页面里叫「术语库」，在按钮、菜单和提示中也沿用这一名称。

**根据情境调整语气。** 导出完成时说明结果即可。采集权限受限或保存失败时，清楚说明影响和可行的处理办法。

| 情境 | 文案 |
| --- | --- |
| 导出完成 | 已导出 12 条记录。 |
| 保存失败 | 无法保存到此文件夹。请选择其他位置。 |

**力求清楚简洁。** 使用含义明确的短句，删去不影响理解的词。把文案放回界面朗读，检查用户能否认出操作对象和结果。

**让更多用户读懂。** 用用户熟悉的词，缩写第一次出现时补充含义。检查长译文、不同书写方向和辅助技术朗读中的文案。

## 最佳实践

**先写最重要的信息。** 标题说明页面用途，例如「字幕外观」「导出记录」。依次安排决定当前任务的选项、必要说明和次要信息。

**用动作命名按钮和链接。** 写「保存」「开始翻译」或「替换文件」，让用户预判结果。链接在独立朗读时也要表意清楚，例如「查看模型要求」。

**重复使用同一语言模式。** 保持按钮、标题和状态文案的写法一致。多步骤流程用明确的起点和终点。需要预告下一步时，可以写「选择音频来源」，流程结束使用「完成」。

**统一英文的大小写规则。** 按界面元素确定大小写写法，在同类标题、按钮和状态中保持一致。品牌和专有名称使用既定拼写。

**删去多余的称呼。** 「收藏」通常已足够清楚。需要使用「你」或「我的」时，保持视角一致。

**按设备描述操作。** 桌面端使用「单击」「右键单击」和快捷键名称，触控场景使用「轻点」「长按」。在共享屏幕或远距离观看的场景中保持内容简短。

**为空白页提供下一步。** 术语库为空时提供「添加术语」，搜索无结果时提示修改搜索词或清除筛选条件。

**在问题附近说明错误与改法。** 文件格式错误可以写「请选择 SRT 或 VTT 文件」。保留用户已输入的信息。

**按紧迫性选择传达方式。** 普通的完成反馈使用轻提示，仍待处理的问题留在相关页面。需要立即决定的事项使用明确的提醒，附上完成判断所需的信息。

**让设置标签说明开启后的行为。** 例如，「显示原文」配「在译文上方保留一行原文」。需要用户更改设置时，提供可以直接打开设置的入口。

**保留可见的输入标签。** 例如字段名「导出文件名」，格式例子「会议记录.srt」。输入开始后，必需的格式说明仍应可见。
