# 多语言与数据格式

让用户以熟悉的语言阅读界面，以所选区域的格式理解数据。原文、译文、文件名和代码各自保留正确的语言与书写方式。

## 语言名称与统一用词

区分界面语言、原文语言和目标语言。语言列表使用语言自身的名称，区域名称在需要区分变体时补充。同一个语言选项在设置、选择器和状态中使用相同名称。

产品名、模型名、文件格式和服务名称沿用其正式写法。翻译界面术语时，连同页面标题、字段和错误一起审阅，保持同一个概念的译法一致。

## 完整句子与变量

以完整句子作为翻译单位，让译文能调整语序。把名称、数量等动态内容作为变量，给翻译者提供它们的含义和使用位置。

数量变化需要覆盖零、单数和复数等相关形式。例如英文的「1 file」「3 files」随数量变化，中文保持「1 个文件」「3 个文件」。范围、单位和句末标点与整句一起处理。

用户输入的名称作为独立内容插入。较长名称可以换行，并在需要辨认或确认时显示完整值。

## 数字与单位

按所选区域显示小数、千位分隔符和单位。下表使用同一个数值，说明不同区域的显示结果。

| 区域 | 数值示例 |
| --- | --- |
| 简体中文（中国） | 1,234.5 |
| 英语（美国） | 1,234.5 |
| 德语（德国） | 1.234,5 |

数值与单位一起呈现，例如「245 MB」「320 ms」。相邻的可比较数据使用相同单位和精度，表头已注明单位时，单元格可以只显示数字。

零值与未知值分别表示。计数为零时显示「0」，没有记录时显示「暂无数据」，等待结果时显示「正在读取」，请求出错时显示「读取失败」并提供重试入口。

技术标识保留原值。模型版本、文件名和接口字段按原样显示，便于识别、查找和复制。

## 日期、时长与字幕时间码

日历日期遵循区域习惯。日期格式可能存在歧义时，补全年份或使用明确的月份名称。需要跨时区理解的记录同时显示时区。

| 内容 | 显示示例 | 规则 |
| --- | --- | --- |
| 日历日期 | 2026年11月7日 / Nov 7, 2026 | 同一天按区域显示 |
| 持续时长 | 1 小时 5 分钟 | 单位随语言变化 |
| SRT 时间码 | 01:05:09,240 | 小时、分钟、秒与毫秒 |
| WebVTT 时间码 | 01:05:09.240 | 按 WebVTT 的分隔符显示 |

时长表示经过多久，时间码表示媒体中的位置。字幕时间码遵循文件格式的字段顺序和分隔符，复制或导出时保留原有精度。

「今天」「刚刚」等相对时间适合近期记录。需要准确引用的时间提供完整值，会议记录等长时间保留的内容应能查看具体日期和时间。

## 标点、空格与大小写

中文句子使用中文标点，英文句子使用英文标点。标题、字段和按钮通常使用简短词组，说明与错误信息按完整句子处理。

英文同类元素采用一致的大小写方式。缩写和专有名称保留规定形式，例如 API、PDF、macOS。数值与拉丁字母单位之间保留空格，快捷键、网址和文件路径遵循各自的写法。

文案引用控件时，保持名称与界面一致。名称自身的标点属于内容，例如文件名中的句点，应随原值保留。

## 长文本与双向文字

为译文增长预留空间，让标签、提示和按钮按内容调整尺寸。重要条件、错误原因和确认对象应完整可读。截断文件名时，提供查看或复制完整名称的途径。

阿拉伯文、希伯来文等内容按自身的书写方向显示。已知语言的段落分别设置语言和方向，来源不定的用户文本可采用自动方向。路径、邮箱和模型 ID 在混合文字中作为独立片段隔离，保留字符次序和复制结果。

界面方向与段落方向分别处理。列表对齐、方向图标和控件行为的完整规则见[从右到左](../foundations/right-to-left)。
